## 0. 개요

**연구 주제.** 완전히 지원되지 않는 질의에 대해 명시적 'unsupported' 성찰 토큰과 응답 내 근거 인용을 결합하여 투명한 거절 또는 외부 지식 요청을 생성하는 방법을 연구한다.

이 연구는 모델이 가진 정보와 근거만으로 충분히 뒷받침되지 않는 질의를 식별하고, 이에 적절히 대응하는 방법을 다룬다. 이를 위해 미지원 질의를 나타내는 명시적 'unsupported' 성찰 토큰을 학습한다. 이 상태를 응답 내 인용과 연결해 투명한 거절 또는 외부 지식 요청을 생성하도록 설계한다. 미지원 질의 벤치마크에서 질의 식별과 응답의 투명성을 검증한다.

## 1. Proposed Method

### 1.1 문제 정의 및 연구 배경

**현재 방식.** RAG [2005.11401]는 외부 비매개변수 메모리에서 지식을 검색해 생성에 활용하고, 생성의 근거를 제공하며 지식 메모리를 갱신할 수 있도록 한다. Self-RAG [2310.11511]는 reflection token을 사용해 검색 필요성을 조절하고 검색 내용과 생성 결과를 평가한다.

**한계.**
- L1. Self-RAG의 {S\&P} 분석에서는 모델이 'irrelevant' 또는 'no support'로 예측한 사례를 고려하지 않는다고 명시한다. 이는 해당 분석의 사례 범위에 관한 제한이며, 이 사실만으로 미지원 질의에 대한 응답 정책이 다뤄지지 않는다고 결론 내릴 수는 없다. [2310.11511]
- L2. Self-RAG는 reflection token으로 검색 여부를 조절하고 검색 문맥과 생성 결과를 평가하며, 'no support' 예측도 언급한다. 다만 관련 설명에 제시된 메커니즘과 달리, 제안 방향은 완전히 지원되지 않는 질의를 독립된 'unsupported' 성찰 상태로 학습하고 이를 투명한 거절 또는 외부 지식 요청으로 연결하는 것을 대상으로 한다. 차이는 판단 대상과 판단 이후 동작에 있다. [2310.11511]
- L3. RAG는 검색된 비매개변수 메모리에 생성을 근거 지어 결정의 출처를 제공하는 것을 목표로 한다. 이 근거 제공 기능과 구별되는 제안 방향은 완전히 지원되지 않는 질의를 명시적으로 판별해 응답 내 인용을 포함한 거절 또는 외부 지식 요청을 생성하는 정책을 다룬다. [2005.11401]
- L4. FineRef는 생성 후 인용별 불일치와 무관성을 성찰하고 교정하는 접근으로 설명된다. 이에 비해 제안 방법은 완전히 지원되지 않는 질의를 판단 대상으로 삼아 생성 중 명시적 'unsupported' 상태를 거절 또는 외부 지식 요청과 인용 응답으로 연결하려는 점에서 판단 대상, 적용 시점, 판단 이후 동작이 다르다. [2602.18437]

**연구 질문.** 완전히 지원되지 않는 질의에서 'unsupported' 성찰 토큰을 학습하고 이를 근거 인용과 연결하면, 해당 질의를 식별하고 투명한 거절 또는 외부 지식 요청을 생성하는 데 도움이 되는지, 그리고 그 수준을 미지원 질의 벤치마크의 식별 지표와 투명성 지표([TBD: 구체적인 지표])로 확인할 수 있는가?

**연구 목표.** 완전히 지원되지 않는 질의에 대해 투명한 거절 또는 외부 지식 요청을 생성하는 방법을 개발하고, 미지원 질의 벤치마크에서 질의 처리와 투명성을 검증한다.

### 1.2 제안 방법

제안 방법은 Self-RAG [2310.11511]의 reflection token 기반 자기성찰에 명시적 'unsupported' 상태를 추가하고, 이를 미지원 질의에 대한 응답 정책과 연결한다. 미지원 상태가 감지되면 응답 내 인용을 포함한 투명한 거절 또는 외부 지식 요청을 생성하도록 설계한다. 인용 표기와 거절 응답에서의 구체적인 인용 적용 방식은 후속 설계 항목으로 둔다.

#### 1.2.1 M1: 미지원 상태 성찰 학습

모델 어휘에 'unsupported' reflection token을 추가하고, 미지원 질의를 해당 토큰으로 표현하도록 reflection 모듈을 미세조정한다. (L1, L2 대응)

#### 1.2.2 M2: 인용 연계 응답 정책

미지원 상태가 감지되면 근거를 응답에 표시하는 인용 생성과 연결해 투명한 거절 또는 외부 지식 요청을 생성한다. 거절 사례에 인용을 적용하는 구체적 방식은 [TBD: 거절 응답에서의 인용 적용 방식]으로 둔다. (L2, L3, L4 대응)

#### 1.2.3 M3: 미지원 학습자료 구성

명시적 'unsupported' 라벨이 있는 질의와 검색 증강 자료의 인용 사례를 마련하고, 관련 논문 말뭉치에서 합성 미지원 질의를 구성한다. 구체적인 라벨 정의와 합성 절차는 [TBD: 미지원 질의 생성 및 라벨링 절차]로 둔다. (L1, L2 대응)

#### 구성요소 관계

- M3 → M1: M3에서 구성한 미지원 라벨 질의와 인용 사례를 M1의 미세조정 자료로 사용한다.
- M1 → M2: M1이 출력한 'unsupported' 상태를 M2의 인용 연계 거절 또는 외부 지식 요청 생성 신호로 사용한다.

## 2. Validation & Target Claims

### 2.1 Experimental Validation Plan

**검증 대상**
- V1. 완전히 지원되지 않는 질의에서 명시적 'unsupported' 성찰 학습이 Self-RAG의 기존 'no support' 판단을 응답 정책에 연결하는 방식보다 미지원 질의 식별 성능을 높이는가? (M1)
- V2. 미지원 상태를 인용 연계 거절 또는 외부 지식 요청으로 연결하면 Self-RAG 및 RAG 기준보다 미지원 질의 응답의 투명성과 근거 표시 품질이 나아지는가? (M2)
- V3. 명시적 미지원 라벨과 합성 미지원 질의를 포함한 학습자료 구성으로 학습하면 동일한 원자료의 기존 라벨을 그대로 사용한 구성보다 미지원 질의 식별 및 응답 정책 성능이 나아지는가? (M3)
- V4. 제안 방법이 원래 답변할 수 있는 지원된 질의에 불필요하게 개입하지 않으면서 Self-RAG 및 RAG 기준의 답변 성능을 유지하는가? (M1, M2)

**비교 대상**
- B1. Self-RAG 기본 방식 [2310.11511] — reflection token으로 검색 필요성과 검색 문맥 및 생성 결과를 평가하는 비교 대상이다. 제안한 미지원 상태 토큰 및 거절·외부 지식 요청 동작을 추가하지 않은 기준으로 사용한다.
- B2. Self-RAG의 기존 'no support' 판단을 이용한 ablation [2310.11511] — 새 'unsupported' 토큰을 학습하지 않고 기존 Self-RAG의 'no support' 판단을 거절 또는 외부 지식 요청 신호로 사용하며, 같은 조건으로 응답에 인용을 연결해 제안 동작을 비교한다. 전용 상태 토큰 학습이 기존 판단 신호보다 필요한지 확인하는 가장 가까운 선행연구 기반 ablation이다.
- B4. 합성 미지원 질의 추가 여부를 비교하는 학습자료 구성 기준 — 동일한 명시적 미지원 라벨 질의 자료를 바탕으로, 제안한 합성 미지원 질의를 추가한 자료와 추가하지 않은 자료로 각각 학습한 결과를 비교한다. 기존 라벨이 별도로 존재한다고 가정하지 않고, 합성 질의 추가에 따른 데이터 구성 효과를 분리한다.

  - 반증 조건: E3에서 제안한 데이터 구성의 미지원 질의 처리 지표가 B4보다 높지 않거나 지원된 질의 성능 저하가 [TBD: 허용 범위]를 넘으면 기각한다.
  - 검증: V3
- **C4.** 제안 방법은 Self-RAG 기본 방식보다 지원된 질의의 답변 성능을 [TBD: 허용 저하 범위] 이내로 유지하면서 미지원 질의 처리를 개선한다.
  - 반증 조건: E4에서 지원된 질의 성능 저하 또는 불필요한 개입률이 정한 허용 기준을 넘거나 미지원 질의 처리가 개선되지 않으면 기각한다.
  - 검증: V4

### 2.3 Expected Novelty & Contribution

**신규성**
- Self-RAG(2310.11511)는 특수 reflection token으로 검색 여부를 조절하고 검색 문맥 및 생성 결과를 평가하며, 'no support' 판단도 사용한다. 이와 달리 제안 방법은 완전히 지원되지 않는 질의를 독립된 'unsupported' 상태로 학습하고 그 상태를 인용을 포함한 거절 또는 외부 지식 요청으로 연결한다. [2310.11511]
  - 기존 장치: Self-RAG는 특수 reflection token으로 검색 여부를 조절하고 검색 문맥 및 생성 결과를 평가한다. 'no support' 예측도 언급되며, 인용된 분석에서는 해당 예측 사례를 고려하지 않는다고 명시한다. · 차이: 판단 이후 동작 · 검증: E1, E2

**기여**
- **방법.** 미지원 질의를 명시적으로 성찰하는 토큰과 이를 인용 연계 거절 또는 외부 지식 요청으로 연결하는 응답 정책을 함께 검증하는 방법을 제안한다.
- **자원.** 명시적 미지원 라벨과 검색 증강 자료의 인용 사례를 포함하는 학습자료 및 보류 평가용 미지원 질의 세트의 구축을 목표로 한다. 구체적인 데이터셋과 구성 절차는 [TBD: 확정 필요]로 둔다.
- **분석.** 완전 미지원 질의의 처리와 지원된 질의에 대한 불필요한 개입 사이의 균형을 기존 방법 및 ablation과 비교해 분석한다.
