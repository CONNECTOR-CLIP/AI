# 연구계획서: 응답 수준 [Unsupported] reflection token과 인용 기반 투명 거절

> run `cot45_public_run_20261029_154552` · candidate 6 · CoT5 판정 NOVEL (검색 범위 한정, 부록 참고)
> 사람이 직접 작성한 정답 예시(golden)이며, `plan.json`만을 근거로 작성했다.

## 0. 개요

검색 증강 언어모델은 찾아온 문서로 답할 수 없을 때도 답을 만들어 내는 경향이 있다. 본 연구는 모델이 "이 근거로는 답할 수 없다"는 상태를 스스로 판단하도록 학습하고, 그때 어떤 문서를 검토했고 무엇이 부족한지 인용과 함께 밝히도록 하는 방법을 제안한다.

## 1. Proposed Method

### 1.1 문제 정의 및 연구 배경

**현재 방식.** RAG [2005.11401]는 검색한 문서를 조건으로 답을 생성한다. Self-RAG [2310.11511]는 reflection token으로 검색 필요성, 문서 관련성, 생성문의 근거 지지 여부를 평가해 인용 정확도를 높였다.

**한계.**
- L1. Self-RAG의 지지 평가는 생성된 문장 단위에 적용된다. 근거 집합 전체가 불충분한 응답 수준의 상태와 그에 따른 거절 정책은 없다 [2310.11511].
- L2. RAG는 검색 품질과 무관하게 답을 생성하므로 근거가 부족할 때 환각이 생길 수 있다 [2005.11401].
- L3. 근거 없는 주장은 주로 생성 후에 탐지 [2504.15771; 2410.07473]하거나 교정 [2602.18437]하며, 생성 시점에 응답 방식을 바꾸지 않는다.
- L4. 근거 부족 시 검색을 반복하는 방식 [2601.04531]은 근거가 끝내 없을 때의 투명한 응답 형식을 정의하지 않는다.

**연구 질문.** 검색 증강 언어모델이 "주어진 근거로는 답할 수 없음"을 명시적 상태로 판별하고, 그 판단을 인용과 함께 투명하게 전달하도록 학습시킬 수 있는가?

### 1.2 제안 방법

Self-RAG의 reflection token 체계에 응답 수준 상태 `[Unsupported]`를 추가한다. 모델은 검색 근거를 읽은 뒤 이 상태를 예측하고, 그 결과에 따라 인용이 달린 답변 또는 인용 기반 거절·외부 지식 요청을 생성한다.

#### 1.2.1 M1: [Unsupported] reflection token
토크나이저에 추가하는 응답 수준 상태 토큰으로, 근거 집합 전체가 질문에 답하기에 불충분한지를 예측한다. (L1, L2 대응)

#### 1.2.2 M2: Unsupported 학습 데이터 구성
답변 가능한 질의에서 정답 근거 문서를 제거하거나 무관한 문서로 바꿔 근거 부족 사례를 합성하고, 원래 사례와 짝지어 라벨을 만든다. (L1 대응)

#### 1.2.3 M3: 인용 결합 응답 생성
지지 상태에서는 인용 답변을, `[Unsupported]` 상태에서는 검토한 문서를 인용하고 부족한 정보를 명시하는 거절 또는 외부 지식 요청을 생성한다. (L3, L4 대응)

#### 1.2.4 M4: 상태 기반 디코딩 정책
`[Unsupported]` 확률에 대한 임계값으로 응답 방식을 고른다. 임계값으로 거절 비율과 답변 성능 사이의 균형을 조절한다. (L2 대응)

#### 구성요소 관계

```
M2 (라벨 생성) ──학습──► M1 (상태 예측) ──확률──► M4 (임계값 정책) ──응답 방식──► M3 (답변 / 인용 거절)
```

|---|---|---|

## 2. Validation & Target Claims

### 2.1 Experimental Validation Plan

**검증 대상**
- V1. M1은 근거 부족 질의를 정확히 판별하는가? (M1, M2)
- V2. `[Unsupported]` 상태의 응답은 검토한 근거와 부족한 정보를 정확히 밝히는가? (M3)
- V3. 답변 가능한 질의에서 답변 성능과 인용 품질이 유지되는가? (M4, M3)
- V4. 효과가 새 토큰 때문인가, 기존 reflection token 임계값만으로도 충분한가? (M1)

**비교 대상**
- B1. RAG [2005.11401]: 거절 장치가 없는 기본 방식
- B2. Self-RAG [2310.11511]: 직접 선행연구
- B3. Self-RAG + 기존 지지 평가 임계값 거절: 새 토큰의 필요성을 보이는 핵심 ablation
- B4. 생성 후 탐지·교정, FineRef [2602.18437]

**Design Table**

| ID | 검증 대상 | 설정 | 지표 | Baseline | 성공 기준 | 실패 시 해석 |
|---|---|---|---|---|---|---|

### 2.2 Target Claims

- **C1.** 응답 수준 `[Unsupported]` 토큰은 기존 reflection token 임계값보다 근거 부족 질의를 더 정확히 판별한다. *반증 조건:* E1·E4에서 B3 대비 유의한 차이가 없음. (검증: V1, V4)
- **C2.** 인용 결합 거절은 무엇이 부족한지 파악할 수 있는 투명한 응답을 만든다. *반증 조건:* E2 사람 평가에서 B2, B4 대비 우위가 없음. (검증: V2)
- **C3.** 적절한 임계값에서 답변 가능한 질의의 성능은 유지된다. *반증 조건:* E3에서 허용 폭 이내의 임계값이 없음. (검증: V3)

### 2.3 Expected Novelty & Contribution

**신규성**
- Self-RAG의 문장 단위 지지 평가 [2310.11511]와 달리, 근거 집합 전체에 대한 응답 수준 상태를 학습한다.
- 생성 후 탐지·교정 [2504.15771; 2602.18437]과 달리, 생성 시점에 응답 방식을 바꾼다.
- 인용 기반 대화 학습 [2603.18911]이나 메모리 기반 접근 [2602.15156]과 달리, 근거 부족 상태를 인용으로 설명하는 거절을 결합한다.

**기여**
- 방법: 응답 수준 `[Unsupported]` reflection token과 인용 결합 응답 생성
- 자원: 근거 부족 사례 합성 절차와 데이터셋
- 분석: 거절률과 답변 성능의 균형, 기존 reflection token과의 비교
