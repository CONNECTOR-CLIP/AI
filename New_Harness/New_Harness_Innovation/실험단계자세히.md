# NEW_HARNESS_INNOVATION 실험 단계 자세히

이 문서는 `NEW_HARNESS_INNOVATION` harness를 직접 실험하기 위한 단계별 실행 가이드입니다.

목표는 다음 흐름을 끝까지 확인하는 것입니다.

```text
입력 JSON 준비
→ run: 논문 정규화 + evidence card 생성 + 후보 생성/비평
→ selection_options 확인
→ select: 후보 선택
→ draft: 초안 생성
→ revise: 질문/수정
→ 산출물 확인
```

> 보안 주의: `.env.local`에는 OpenRouter API key가 들어갑니다. 이 파일은 열람/공유/커밋하지 마세요.

---

## 0. 작업 위치 확인

먼저 프로젝트 폴더로 이동합니다.

```bash
cd /mnt/d/NEW_HARNESS_INNOVATION
```

Python 3.11 이상을 권장합니다.

```bash
python3 --version
```

현재 테스트가 통과하는지 빠르게 확인하려면:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py' -v
```

정상 기준:

```text
Ran 51 tests ... OK
```

## 1. OpenRouter 키 준비

이미 `.env.local`에 키를 넣었다면 이 단계는 다시 하지 않아도 됩니다.

키 파일이 없을 때만:

```bash
cp .env.example .env.local
```

그 다음 `.env.local`에 아래처럼 키를 넣습니다.

```text
OPENROUTER_API_KEY=여기에_본인_OpenRouter_키
OPENROUTER_MODEL=~openai/gpt-latest
```

모델을 바꾸고 싶으면 `OPENROUTER_MODEL` 값을 변경하거나 실행 시 `--openrouter-model`을 사용하면 됩니다.

예:

```bash
python3 -m new_harness.cli run \
  --input my_input.json \
  --run-id my-run \
  --run-root "$RUN_ROOT" \
  --provider openrouter \
  --openrouter-model "원하는/모델명"
```

> 중요: `.env.local`은 `.gitignore`에 의해 제외됩니다. 그래도 직접 복사하거나 채팅에 붙여넣지 마세요.

## 2. 실험 입력 JSON 만들기

입력은 arXiv ID 또는 arXiv URL만 지원합니다. PDF 다운로드나 PDF 파싱은 하지 않습니다.

가장 간단한 입력 파일 예시:

```bash
cat > my_input.json <<'JSON'
{
  "selected_papers": [
    {
      "source": "2401.14196",
      "title": "실험용 선택 논문"
    }
  ],
  "user_draft": {
    "memo_text": "이 논문을 바탕으로 후속 연구 아이디어를 만들고 싶다. 평가 계획과 novelty risk를 특히 보고 싶다."
  }
}
JSON
```

여러 논문을 넣고 싶으면:

```json
{
  "selected_papers": [
    { "source": "2401.14196", "title": "첫 번째 논문" },
    { "source": "https://arxiv.org/abs/2401.14196" },
    { "source": "cs/9901001", "title": "구형 arXiv ID 예시" }
  ],
  "user_draft": {
    "draft_text": "이미 작성한 초안이 있다면 여기에 넣을 수 있습니다.",
    "memo_text": "추가 지시나 메모를 여기에 넣습니다."
  }
}
```

입력 규칙:

- `selected_papers`는 필수입니다.
- 각 논문은 `source`가 필수입니다.
- `source`는 arXiv ID 또는 `https://arxiv.org/abs/...` / `https://arxiv.org/pdf/...` 형태만 허용됩니다.
- URL이 PDF URL이어도 실제 PDF를 다운로드하지 않습니다.
- `user_draft`는 선택입니다.

## 3. 실험용 run root 만들기

산출물을 프로젝트 안에 섞지 않으려면 임시 폴더를 쓰는 것이 좋습니다.

```bash
RUN_ROOT="$(mktemp -d)"
echo "$RUN_ROOT"
```

이후 모든 산출물은 다음 아래에 생깁니다.

```text
$RUN_ROOT/runs/<run_id>/
```

run id는 실험 이름처럼 정하면 됩니다.

```bash
RUN_ID="exp-openrouter-001"
```

## 4. OpenRouter로 후보 생성 실행

실제 OpenRouter 호출을 사용하는 기본 실험:

```bash
python3 -m new_harness.cli run \
  --input my_input.json \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT" \
  --provider openrouter \
  --verification-depth selected_only
```

성공하면 대략 이런 JSON이 출력됩니다.

```json
{
  "status": "selection_required",
  "metadata": {
    "pass_candidate_ids": ["cand-r1-1", "cand-r1-2", "cand-r1-3"],
    "rounds_completed": 1
  }
}
```

의미:

- `selection_required`: 후보가 생성되었고, 사람이 하나를 선택해야 합니다.
- `pass_candidate_ids`: 선택 가능한 후보 ID 목록입니다.
- `rounds_completed`: 후보 생성/비평 라운드 수입니다.

만약 `blocked`가 나오면:

- pass 후보가 없다는 뜻입니다.
- `candidate_loop.json`의 `best_revise_candidate_ids`를 보고 입력/메모를 보강한 뒤 다시 실행하세요.

## 5. 생성된 산출물 확인

실행 후 산출물 목록:

```bash
find "$RUN_ROOT/runs/$RUN_ID" -maxdepth 3 -type f | sort
```

주요 파일:

```text
selected_papers.normalized.json       # 입력 논문 정규화 결과
evidence_cards/index.json             # evidence card 목록
evidence_cards/<paper_id>.json        # 논문별 evidence card
candidates/candidates_round_1.json    # 생성 후보
critic_reports/critic_reports_round_1.json  # 후보 비평 결과
candidate_loop.json                   # 전체 후보 루프 요약
selection_options.json                # 선택 가능한 후보 JSON
selection_options.md                  # 사람이 읽기 좋은 선택지
```

사람이 먼저 볼 파일은 보통 이것입니다.

```bash
cat "$RUN_ROOT/runs/$RUN_ID/selection_options.md"
```

후보의 상세 JSON을 보고 싶으면:

```bash
python3 -m json.tool "$RUN_ROOT/runs/$RUN_ID/candidates/candidates_round_1.json" | less
```

비평 결과를 보고 싶으면:

```bash
python3 -m json.tool "$RUN_ROOT/runs/$RUN_ID/critic_reports/critic_reports_round_1.json" | less
```

## 6. 후보 선택하기

`selection_options.md`를 읽고 마음에 드는 후보 ID를 고릅니다.

예: `cand-r1-1`을 선택하는 경우

```bash
CANDIDATE_ID="cand-r1-1"

python3 -m new_harness.cli select \
  --run-id "$RUN_ID" \
  --candidate-id "$CANDIDATE_ID" \
  --run-root "$RUN_ROOT"
```

성공하면 다음 파일이 생깁니다.

```text
$RUN_ROOT/runs/$RUN_ID/selected_candidate.json
```

확인:

```bash
python3 -m json.tool "$RUN_ROOT/runs/$RUN_ID/selected_candidate.json" | less
```

주의:

- `pass_candidate_ids`에 없는 후보는 선택할 수 없습니다.
- 선택은 `run_id`에 묶입니다. 다른 run의 후보를 섞어 쓰지 않습니다.

## 7. 초안 생성하기

후보를 선택한 뒤 draft를 생성합니다.

```bash
python3 -m new_harness.cli draft \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT"
```

생성 파일:

```text
draft.md
draft.claim_map.json
```

초안 보기:

```bash
cat "$RUN_ROOT/runs/$RUN_ID/draft.md"
```

claim map 보기:

```bash
python3 -m json.tool "$RUN_ROOT/runs/$RUN_ID/draft.claim_map.json" | less
```

`draft.claim_map.json`에는 초안의 주장, evidence trace, risk notes가 들어갑니다.

## 8. 수정/질문하기: qa_suggest

`qa_suggest`는 초안을 직접 바꾸지 않고, 질문에 대한 답변/수정 제안을 JSON 기록으로 남깁니다.

```bash
python3 -m new_harness.cli revise \
  --run-id "$RUN_ID" \
  --mode qa_suggest \
  --request "초록과 결론에서 어떤 부분을 강화하면 좋을까?" \
  --run-root "$RUN_ROOT"
```

결과:

```text
revisions/qa_suggest-<hash>.json
```

확인:

```bash
ls "$RUN_ROOT/runs/$RUN_ID/revisions"
python3 -m json.tool "$RUN_ROOT/runs/$RUN_ID/revisions/qa_suggest-"*.json | less
```

특징:

- `draft.md`는 변경하지 않습니다.
- 동일 요청을 반복해도 기존 기록을 덮어쓰지 않고 `-02.json`, `-03.json`처럼 새 파일을 만듭니다.

## 9. 초안 직접 수정하기: auto_edit

`auto_edit`는 `draft.md`에 `## Revision Update` 섹션을 추가하고, revision record도 남깁니다.

```bash
python3 -m new_harness.cli revise \
  --run-id "$RUN_ID" \
  --mode auto_edit \
  --request "평가 계획을 더 명확하게 보강해줘." \
  --run-root "$RUN_ROOT"
```

확인:

```bash
cat "$RUN_ROOT/runs/$RUN_ID/draft.md"
ls "$RUN_ROOT/runs/$RUN_ID/revisions"
```

특징:

- `draft.md` 끝에 새 `## Revision Update` 섹션을 추가합니다.
- 이전 `## Revision Update` 섹션을 지우지 않습니다.
- 전체 수정 이력은 `revisions/` 아래 JSON으로 계속 보존됩니다.

## 10. 전체 실험을 한 번에 실행하는 예시

아래는 한 번에 run → select → draft → revise까지 진행하는 예시입니다.

```bash
cd /mnt/d/NEW_HARNESS_INNOVATION

cat > my_input.json <<'JSON'
{
  "selected_papers": [
    {
      "source": "2401.14196",
      "title": "실험용 선택 논문"
    }
  ],
  "user_draft": {
    "memo_text": "후속 연구 아이디어, 평가 계획, novelty risk를 확인하고 싶다."
  }
}
JSON

RUN_ROOT="$(mktemp -d)"
RUN_ID="exp-openrouter-001"

echo "RUN_ROOT=$RUN_ROOT"

python3 -m new_harness.cli run \
  --input my_input.json \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT" \
  --provider openrouter \
  --verification-depth selected_only

cat "$RUN_ROOT/runs/$RUN_ID/selection_options.md"

CANDIDATE_ID="cand-r1-1"

python3 -m new_harness.cli select \
  --run-id "$RUN_ID" \
  --candidate-id "$CANDIDATE_ID" \
  --run-root "$RUN_ROOT"

python3 -m new_harness.cli draft \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT"

python3 -m new_harness.cli revise \
  --run-id "$RUN_ID" \
  --mode qa_suggest \
  --request "이 초안에서 가장 약한 claim과 보강 방법을 알려줘." \
  --run-root "$RUN_ROOT"

python3 -m new_harness.cli revise \
  --run-id "$RUN_ID" \
  --mode auto_edit \
  --request "평가 계획과 한계 부분을 더 명확히 보강해줘." \
  --run-root "$RUN_ROOT"

cat "$RUN_ROOT/runs/$RUN_ID/draft.md"
```

## 11. offline/fake 모드로 먼저 테스트하기

OpenRouter 비용을 쓰기 전에 fake provider로 흐름만 확인할 수 있습니다.

```bash
RUN_ROOT="$(mktemp -d)"
RUN_ID="exp-fake-001"

python3 -m new_harness.cli run \
  --input tests/fixtures/selected_papers_arxiv.json \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT" \
  --provider fake \
  --verification-depth selected_only
```

또는 `--provider`를 생략해도 기본값은 `fake`입니다.

```bash
python3 -m new_harness.cli run \
  --input tests/fixtures/selected_papers_arxiv.json \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT"
```

fake 모드는 deterministic하므로 테스트/디버깅에 좋습니다.

## 12. verification-depth 옵션

`run`에는 3가지 검증 깊이가 있습니다.

| 옵션 | 의미 | 현재 동작 |
| --- | --- | --- |
| `selected_only` | 선택 논문 evidence만 사용 | 외부 novelty check 생략 |
| `light_external` | pass/near-pass 후보 일부만 외부 확인 | `--external-checker`를 지정하면 대상 후보만 검사. checker가 없거나 실패하면 degraded report 기록 |
| `strong_external` | 모든 후보를 강하게 외부 확인 | `--external-checker`를 지정하면 모든 후보 검사. checker가 없거나 실패하면 모든 후보 degraded report 기록 |

일반 실험은 우선 `selected_only`를 추천합니다.

```bash
--verification-depth selected_only
```

외부 novelty check 구조를 확인하고 싶으면:

```bash
--verification-depth light_external
```

또는:

```bash
--verification-depth strong_external
```

현재 CLI는 별도 external checker를 설정하지 않으면 novelty check 결과를 `degraded`로 기록합니다. 이는 조용히 통과시키는 것이 아니라, “외부 검증이 아직 충분하지 않다”는 상태를 명시적으로 남기는 동작입니다.

실제 외부 검색을 수행하려면 `--external-checker`를 지정합니다.

```bash
--external-checker arxiv_api
```

범용 웹 검색 JSON endpoint가 있으면:

```bash
python3 -m new_harness.cli run \
  --input my_input.json \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT" \
  --provider openrouter \
  --verification-depth strong_external \
  --external-checker web \
  --external-search-url "https://example-search-proxy.local/search" \
  --external-search-query-param q \
  --external-max-results 5
```

`D:/SearchEngine`의 FastAPI 검색 서비스가 실행 중이면:

```bash
python3 -m new_harness.cli run \
  --input my_input.json \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT" \
  --provider openrouter \
  --verification-depth strong_external \
  --external-checker search_engine \
  --external-search-url "http://127.0.0.1:8000/search"
```

`search_engine` checker는 `D:/SearchEngine`의 `/search?query=...&mode=all&sort=relevance&page=1&size=...` 응답 형식을 사용합니다.

## 14. 문제 해결

### 14.1 `OPENROUTER_API_KEY is required`가 나오는 경우

원인:

- `.env.local`에 키가 없거나
- 다른 env 파일을 지정했는데 그 파일에 키가 없거나
- 현재 작업 디렉터리가 프로젝트 루트가 아닐 수 있습니다.

확인할 것:

```bash
pwd
ls -la .env.local
```

키 값 자체는 터미널에 출력하지 마세요.

### 14.2 HTTP 401 / Unauthorized

가능한 원인:

- OpenRouter 키가 잘못됨
- 키 앞뒤에 공백/따옴표가 잘못 들어감
- 계정 권한 문제

조치:

- `.env.local`에서 키를 다시 넣습니다.
- 키 값은 공유하지 않습니다.

### 14.3 HTTP 429 / rate limit

가능한 원인:

- 너무 자주 호출함
- 계정/모델 rate limit

조치:

- 잠시 기다린 뒤 재실행합니다.
- 후보 수가 많아지면 호출 비용/시간도 늘 수 있습니다.

### 14.4 `selection_required`인데 draft가 안 만들어지는 경우

정상입니다. 먼저 후보를 선택해야 합니다.

```bash
cat "$RUN_ROOT/runs/$RUN_ID/selection_options.md"
python3 -m new_harness.cli select \
  --run-id "$RUN_ID" \
  --candidate-id cand-r1-1 \
  --run-root "$RUN_ROOT"
```

그 다음 draft:

```bash
python3 -m new_harness.cli draft \
  --run-id "$RUN_ID" \
  --run-root "$RUN_ROOT"
```

### 14.5 `blocked`가 나오는 경우

후보가 pass 기준을 통과하지 못한 것입니다.

확인:

```bash
python3 -m json.tool "$RUN_ROOT/runs/$RUN_ID/candidate_loop.json" | less
```

대응:

- 입력 논문을 늘립니다.
- `user_draft.memo_text`에 원하는 연구 방향을 더 구체적으로 씁니다.
- 제목/초록 정보가 부족하면 더 풍부한 metadata를 입력에 넣는 방향을 고려합니다.
