# 폴더
각 New_Harness_Innovation/experiment_work_*/runs/ 폴더에 있으며 보는 방법은 다음과 같다.

### 1. 최종 사람이 읽을 결과

  draft.md

  선택된 연구 아이디어를 바탕으로 만들어진 최종 초안입니다.
  현재 선택된 후보는:

  cand-r1-1
  Limitation-Targeted Stress Benchmark for Deterministic Methods

  즉 draft.md는 cand-r1-1 기반입니다.

  ———

### 2. 후보 비교용 파일

  selection_options.md

  사람이 읽기 좋게 후보 3개를 요약한 파일입니다.

  현재 후보는:

  cand-r1-1
  cand-r1-2
  cand-r1-3

  전부 critic 기준은 통과했습니다. 다만 light_external 모드라서 외부 검색 검증은 일
  부만 했습니다.

  ———

  ### 3. 전체 후보 루프 요약

  candidate_loop.json

  후보 생성/비평 루프의 상태 요약입니다.

  현재 의미는 대략:

  rounds_completed: 1
  pass_candidate_ids: cand-r1-1, cand-r1-2, cand-r1-3
  status: selection_required 또는 완료 후 선택됨

  즉 후보 3개가 생성됐고 모두 pass였습니다.

  ———

  ## 단계별 생성물 의미

  ### A. 입력/정규화

  01_실험입력_5개_arxiv.json
  selected_papers.normalized.json
  user_draft.json

  - 01_실험입력_5개_arxiv.json: 네가 넣은 원본 입력
  - selected_papers.normalized.json: arXiv ID를 표준 메타데이터 형태로 정리한 것
  - user_draft.json: 사용자가 넣은 메모/초안 저장본

  ———

  ### B. 논문별 evidence 추출

  evidence_cards/
    index.json
    2401.14196.json
    2505.18705.json
    ...

  각 논문에서 claim, method, limitation, future work clue 같은 근거를 뽑은 카드입니
  다.

  쉽게 말하면:

  논문 5개 → evidence card 5개

  index.json은 evidence card 목록입니다.

  ———

  ### C. 연구 후보 생성

  candidates/candidates_round_1.json

  evidence card들을 바탕으로 만든 연구 아이디어 후보들입니다.

  각 candidate 안에는 보통 이런 내용이 있습니다.

  candidate_id
  title
  gap_statement
  hypothesis
  proposed_method
  evaluation_plan
  expected_contribution
  risks
  supporting_evidence_refs

  ———

  ### D. 외부 검색 검증

  external_checks/round_1/cand-r1-1.json
  external_checks/round_1/cand-r1-2.json

  여기가 search_engine_light의 핵심 차이입니다.

  현재 실행은 light_external이라서 모든 후보를 검사하지 않고 상위 일부만 외부 검색했
  습니다.

  현재 상태:

  cand-r1-1: external check 됨, duplicate_risk = low
  cand-r1-2: external check 됨, duplicate_risk = low
  cand-r1-3: light_external_skipped

  strong_external이면 보통 모든 후보를 외부 검색합니다.

  ———

  ### E. 후보 비평 결과

  critic_reports/critic_reports_round_1.json

  각 후보에 대해 critic이 점수를 준 결과입니다.

  확인할 포인트:

  verdict
  evidence_score
  feasibility_score
  novelty_risk
  verification_status
  weaknesses
  required_fixes

  현재는 후보 3개 모두 pass입니다.

  ———

  ### F. 후보 선택 결과

  selected_candidate.json

  최종으로 선택된 후보 하나를 저장합니다.

  현재는:

  cand-r1-1

  이후 draft.md와 draft.claim_map.json은 이 선택 후보 기반으로 생성됩니다.

  ———

  ### G. 초안과 claim map

  draft.md
  draft.claim_map.json

  - draft.md: 최종 초안
  - draft.claim_map.json: 초안의 주장들이 어떤 evidence card에 연결되는지 추적한 파
    일

  draft.claim_map.json은 사람이 바로 읽기엔 복잡하지만, “이 문장이 어느 논문 근거에
  서 나왔나?”를 검증할 때 중요합니다.

  ———

  ### H. 수정/질문 기록

  revisions/
    qa_suggest-....json
    auto_edit-....json

  - qa_suggest: 초안은 안 바꾸고, 질문에 대한 제안만 기록
  - auto_edit: 실제로 draft.md를 수정하고 기록

  현재는 둘 다 한 번씩 실행된 상태입니다.

  ———

  ### I. 실행 로그

  events.jsonl

  디버깅용 타임라인입니다.

  흐름은 대략 이 순서였습니다.

  ingest
  → evidence
  → candidate_generation_round_1
  → candidate_critic_round_1
  → candidate_loop
  → selection
  → draft
  → revise_qa_suggest
  → revise_auto_edit

  ## 한 줄 요약

  이 폴더는:

  5개 arXiv 입력
  → 논문별 evidence card 생성
  → 연구 후보 3개 생성
  → light_external 방식으로 후보 2개만 외부 검색 검증
  → critic 평가
  → cand-r1-1 선택
  → draft.md 초안 생성
  → revision 기록 저장

  한 것입니다.

  가장 먼저 보면 되는 파일은 이 순서입니다.

  1. selection_options.md
  2. selected_candidate.json
  3. draft.md
  4. draft.claim_map.json
  5. critic_reports/critic_reports_round_1.json
  6. external_checks/round_1/*.json
