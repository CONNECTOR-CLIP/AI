# 바꿀 수 있는 파라미터

현재 `NEW_HARNESS_INNOVATION` CLI에서 사용자가 직접 바꿀 수 있는 설정과, 코드 내부에는 있지만 아직 CLI로 노출되지 않은 설정을 정리합니다.

## 1. 현재 사용자가 직접 설정 가능한 것

### 1.1 `run` 명령

```bash
python3 -m new_harness.cli run
```

| 설정 | 가능 값 | 의미 |
| --- | --- | --- |
| `--input` | JSON 파일 경로 | 입력 논문/메모 JSON |
| `--run-id` | 문자열 | 실험 ID |
| `--run-root` | 폴더 경로 | 산출물 저장 루트 |
| `--provider` | `fake`, `openrouter` | LLM provider 선택 |
| `--openrouter-model` | 모델명 문자열 | OpenRouter 모델 override |
| `--env-file` | env 파일 경로 | `.env.local` 대신 쓸 env 파일 |
| `--verification-depth` | `selected_only`, `light_external`, `strong_external` | 외부검증 정책 수준 |
| `--external-checker` | `none`, `arxiv_api`, `web`, `search_engine` | 외부 검색/checker 종류 |
| `--external-check-top-k` | 양의 정수 | `light_external`에서 검사할 상위 후보 수 |
| `--external-max-results` | 양의 정수 | external checker가 가져올 검색 결과 수 |
| `--external-timeout` | 초 단위 숫자 | external checker HTTP 요청 timeout |
| `--external-min-interval` | 초 단위 숫자 | external checker 요청 사이 최소 간격 |
| `--external-search-url` | URL | `web`/`search_engine` checker endpoint |
| `--external-search-query-param` | 문자열 | `web` checker에서 검색어를 담을 query parameter 이름. 기본 `q` |
| `--external-search-api-key-env` | env var 이름 | `web` checker API key를 읽을 환경변수 이름 |
| `--external-search-api-key-header` | HTTP header 이름 | API key를 넣을 header 이름. 기본 `X-Subscription-Token` |

### 1.2 `select` 명령

```bash
python3 -m new_harness.cli select
```

| 설정 | 의미 |
| --- | --- |
| `--run-id` | 대상 run |
| `--candidate-id` | 선택할 후보 |
| `--run-root` | 산출물 루트 |

### 1.3 `draft` 명령

```bash
python3 -m new_harness.cli draft
```

| 설정 | 의미 |
| --- | --- |
| `--run-id` | 대상 run |
| `--run-root` | 산출물 루트 |

### 1.4 `revise` 명령

```bash
python3 -m new_harness.cli revise
```

| 설정 | 가능 값 / 의미 |
| --- | --- |
| `--mode` | `qa_suggest` 또는 `auto_edit` |
| `--request` | 수정/질문 요청문 |
| `--run-id` | 대상 run |
| `--run-root` | 산출물 루트 |

## 2. `.env.local`에서 설정 가능한 것

```env
OPENROUTER_API_KEY=...
OPENROUTER_MODEL=...
```

즉 사용자는 OpenRouter 키와 기본 모델을 바꿀 수 있습니다.

웹 검색 API key는 `.env.local` 또는 셸 환경변수에 넣고, 실행 시 `--external-search-api-key-env`로 환경변수 이름만 넘기는 방식이 안전합니다.

## 3. `verification-depth` 의미

| 값 | 의미 | 현재 CLI 동작 |
| --- | --- | --- |
| `selected_only` | 외부 검색 없이 입력 논문 evidence만 사용 | 외부 novelty check 안 함 |
| `light_external` | pass 또는 near-pass 후보 일부만 외부 확인 | `--external-checker`가 있으면 일부 후보만 검사. 없거나 실패하면 `degraded` 기록 |
| `strong_external` | 모든 후보를 외부 확인 | `--external-checker`가 있으면 모든 후보 검사. 없거나 실패하면 `degraded` 기록 |

간단히 말하면:

```text
selected_only   = 외부 검색 안 함
light_external  = 좋은 후보 일부만 외부 검색 정책
strong_external = 모든 후보 외부 검색 정책
```

## 4. `--external-checker` 의미

| 값 | 의미 | 비고 |
| --- | --- | --- |
| `none` | external checker 없음 | 기본값. `light_external`/`strong_external`에서는 degraded 기록 |
| `arxiv_api` | arXiv Atom API metadata-only 검색 | PDF 다운로드 없음 |
| `web` | 범용 JSON 웹 검색 API/프록시 사용 | `--external-search-url` 필요 |
| `search_engine` | `D:/SearchEngine` FastAPI `/search` 서비스 사용 | 기본 URL `http://127.0.0.1:8000/search` |

## 5. 실행 예시

### 5.1 범용 web 검색 endpoint 사용

```bash
python3 -m new_harness.cli run \
  --input my_input.json \
  --run-id exp-web-strong \
  --run-root "$RUN_ROOT" \
  --provider openrouter \
  --verification-depth strong_external \
  --external-checker web \
  --external-search-url "https://example-search-proxy.local/search" \
  --external-search-query-param q \
  --external-max-results 5
```

API key가 필요한 경우:

```bash
export WEB_SEARCH_API_KEY="..."
python3 -m new_harness.cli run \
  --input my_input.json \
  --run-id exp-web-key \
  --run-root "$RUN_ROOT" \
  --provider openrouter \
  --verification-depth strong_external \
  --external-checker web \
  --external-search-url "https://api.search.example/web/search" \
  --external-search-api-key-env WEB_SEARCH_API_KEY \
  --external-search-api-key-header X-Subscription-Token
```

### 5.2 D:/SearchEngine 연동

`D:/SearchEngine` FastAPI 서버가 실행 중이면:

```bash
python3 -m new_harness.cli run \
  --input my_input.json \
  --run-id exp-search-engine-strong \
  --run-root "$RUN_ROOT" \
  --provider openrouter \
  --verification-depth strong_external \
  --external-checker search_engine \
  --external-search-url "http://127.0.0.1:8000/search"
```

`search_engine` checker는 아래 형식의 API를 기대합니다.

```text
GET /search?query=<검색어>&mode=all&sort=relevance&page=1&size=<external-max-results>
```

응답은 `D:/SearchEngine`의 `SearchResponse` 형식입니다.

```json
{
  "total": 1,
  "page": 1,
  "size": 5,
  "results": [
    {
      "arxiv_id": "2401.00001",
      "title": "...",
      "abstract": "...",
      "authors": ["..."],
      "categories": ["cs.AI"],
      "published": "2024-01-01",
      "score": 12.5
    }
  ]
}
```

## 6. 코드 내부에는 있지만 현재 CLI로는 직접 못 바꾸는 설정

아래 critic/generation 관련 값들은 아직 CLI 옵션이 없습니다.

```text
candidates_per_round
max_candidate_rounds
evidence_pass_threshold
feasibility_pass_threshold
near_pass_margin
```

## 7. 결론

현재 사용자가 직접 고를 수 있는 핵심 파라미터는 다음입니다.

```text
입력 JSON
run-id
run-root
provider: fake/openrouter
OpenRouter 모델
env 파일
verification-depth: selected_only/light_external/strong_external
external-checker: none/arxiv_api/web/search_engine
external 검색 결과 수, timeout, 요청 간격
web/search_engine endpoint URL
web API key 환경변수 이름/header 이름
select할 candidate-id
revise mode: qa_suggest/auto_edit
revise request 문장
```

아직 CLI에서 직접 고를 수 없는 것은 후보 생성 개수, 후보 라운드 수, critic threshold, near-pass margin입니다.
