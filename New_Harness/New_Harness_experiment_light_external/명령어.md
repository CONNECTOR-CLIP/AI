# 명령어.md

OpenRouter provider + light_external + D:/SearchEngine 실제 검색 재실험 명령 기록입니다.
`새로운하네스실험_strong_external`과 동일한 입력(arXiv 5편)으로, `--verification-depth`만 `light_external`로 바꿔 비교 실험했습니다.

## 실행 정보

- RUN_ID: `exp-openrouter-search-engine-light-20260707`
- Provider: `openrouter`
- verification-depth: `light_external`
- external-checker: `search_engine`
- SearchEngine URL: `http://127.0.0.1:8000/search`
- Python/uvicorn: `D:/.venv-local-win`
- OpenSearch: `D:/opensearch-2.13.0`, bundled JDK 사용
- `.env.local`: 파일 내용을 확인/출력하지 않았고, CLI 자동 로드만 사용했습니다.

## 서버 실행

이번 실험 시점에는 SearchEngine(FastAPI)과 OpenSearch가 이미 실행 중이었습니다(`strong_external` 실험 이후 계속 기동 상태).

```bash
curl http://127.0.0.1:8000/health
# {"status":"ok","opensearch":"connected"}
curl http://127.0.0.1:9200/_cluster/health
# status: green
```

## run 명령

```bash
/mnt/d/.venv-local-win/Scripts/python.exe -m new_harness.cli run \
  --input "D:\NEW_HARNESS_INNOVATION\experiment_work_search_engine_light\01_실험입력_5개_arxiv.json" \
  --run-id "exp-openrouter-search-engine-light-20260707" \
  --run-root "D:\NEW_HARNESS_INNOVATION\experiment_work_search_engine_light\run_root" \
  --provider openrouter \
  --verification-depth light_external \
  --external-checker search_engine \
  --external-search-url "http://127.0.0.1:8000/search" \
  --external-max-results 5 \
  --external-timeout 20 \
  --external-min-interval 0.5
```

## 참고: unittest 결과 관련 메모

이번 실험 환경(Windows 네이티브 `D:/.venv-local-win/Scripts/python.exe`, Python 3.12.8)에서 `python -m unittest discover`를 실행하면 54개 중 53개는 통과하고, `test_evidence.py`의 `test_evidence_stage_creates_one_card_per_selected_paper_and_index` 1개가 실패합니다. 원인은 `evidence_cards/index.json`의 `card_path`가 Windows에서 `evidence_cards\2401.14196.json`(백슬래시)으로 기록되는데 테스트는 `evidence_cards/2401.14196.json`(슬래시)을 기대하기 때문입니다. `strong_external` 실험 문서의 "54개 OK" 기록은 WSL/Linux `python3` 환경에서 실행된 결과로 보이며, 이번 light_external 실험은 실제 CLI 실행 자체에는 영향이 없는 것을 확인했습니다(harness 코드의 사전 존재 이슈이며 이번 실험 범위에서 수정하지 않았습니다).
